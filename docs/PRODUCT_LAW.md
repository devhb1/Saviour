# Saviour Product Law (Privilege Guard)

1. **Day-1 product is Privilege Guard** — Review + Watch. ENS / Base registry / agents are phase-2 or legacy.
2. **SAFE is never a named status.** Miss → `NO_VERDICT` — never ALLOW-by-absence.
3. **`NO_VERDICT` does not auto-block.** Wallets show unknown; their policies decide.
4. **Resolve ≠ Assess.** Address memory and transaction assessment are separate APIs.
5. **Risk and coverage are orthogonal.** Unsupported never overwrites TAINTED; partial decode never looks fully assessed.
6. **CRITICAL privilege decode → vault WATCH / WARN.** TAINTED requires Attester. AI never alone finalizes TAINTED.
7. **DELEGATECALL is contextual** — not auto-CRITICAL.
8. **Static decode ≠ full simulation.** Never claim guaranteed execution outcomes.
9. **Two modes:** Watch (queued privilege ops) ≠ Review (imported Safe/calldata). Do not conflate demos.
10. **Safe review** is import/paste until a full pending-tx integration ships — do not claim all Safe pending transactions.
11. **Signer decides.** Saviour explains; it does not enforce a block unless a wallet integration does.
12. **Sepolia ENS = legacy/staging.** Base registry = optional phase-2 memory — not required for Watch/Review.
13. **`$0` resolve** (when registry live) = no Saviour protocol fee; RPC infra still has operating cost.
